# 전성 포트폴리오 웹사이트 구성안

## 1. 사이트의 목적

채용 담당자가 첫 화면에서 1분 안에 아래 세 가지를 파악하도록 만든다.

1. 전성이 어떤 방식으로 개발하는 사람인지
2. DONDOK과 DEVNEAR가 실제로 어떤 서비스인지
3. 실제로 맡아 구현한 범위가 무엇인지

이 사이트는 모든 개발 기록을 쌓는 기술 블로그가 아니다. 핵심 내용만 보여주고, 코드와 상세 자료가 필요한 사람을 GitHub와 Notion으로 연결하는 채용용 포트폴리오다.

## 2. 핵심 메시지

> 백엔드를 중심으로 개발하되, 기능이 실제 화면과 사용자 흐름에서 어떻게 이어지는지까지 확인합니다.

강조 순서는 다음과 같다.

1. DONDOK과 DEVNEAR의 실제 사용자 흐름
2. 화면까지 연결해 결과를 확인하는 개발 방식
3. 백엔드 API와 상태 흐름 구현 경험

## 3. 전체 페이지 구조

### `/` 홈

한 페이지 안에서 전성의 핵심을 빠르게 훑는 화면이다.

1. **Hero**
   - 이름과 한 줄 소개
   - PR 영상 또는 짧은 자기소개 영상
   - 프로젝트 보기, GitHub, 이력서 버튼
2. **Selected Projects**
   - DONDOK
   - DEVNEAR
   - 서비스 설명, 담당 역할, 핵심 구현 2~3개만 노출
   - 각 프로젝트의 핵심 화면을 바로 체험할 수 있는 `미리 체험하기` 제공
3. **How I Work**
   - API 구현 이후 실제 화면까지 확인
   - AI 초안과 리뷰 결과를 코드·동작으로 재검증
   - 요구사항과 일정에 따라 구현 범위를 조정
4. **Experience**
   - AI Team Internship
   - 생성형 AI 백엔드 과정
   - 프로젝트명을 반복하지 않고 기간과 역할만 간결하게 표시
5. **About / Contact**
   - 짧은 자기소개
   - 이메일, GitHub, Notion, 이력서 다운로드

### `/ai-usage`

AI를 많이 사용했다는 설명보다, 어떻게 통제하고 검증했는지 보여주는 페이지다.

### Readle 처리 방식

Readle은 홈의 경력 항목에서 **인턴십 경험**으로만 간단히 소개한다. 대표 프로젝트와 같은 깊이의 상세 페이지는 만들지 않는다. 팀 리딩, 범위 조정, 화면 연동 경험을 중심으로 3줄 이내로 정리한다.

## 4. 서비스 체험 방식

두 프로젝트를 처음 보는 사람도 설명 없이 이해할 수 있도록 포트폴리오 안에 짧은 인터랙티브 데모를 만든다.

- 별도의 회원가입과 로그인 없이 바로 시작
- 실제 서버 대신 포트폴리오에 포함된 샘플 데이터 사용
- 원본 서비스 전체가 아니라 핵심 사용자 흐름 3~4단계만 재현
- 현재 단계와 다음 행동을 화면에 명확하게 표시
- 체험 종료 후 `이 흐름에서 제가 구현한 부분`으로 자연스럽게 연결
- 실제 운영 서비스로 오해하지 않도록 `포트폴리오용 데모 · 샘플 데이터` 표기
- 모바일 화면은 휴대전화 프레임, 웹 화면은 브라우저 프레임으로 표현

### DONDOK 데모의 목표

보증금을 걸고 습관 크루에 참여한 뒤, 활동 결과에 따라 환급받는 서비스라는 점을 한 번의 흐름으로 이해하게 한다.

### DEVNEAR 데모의 목표

지역과 기술 조건을 기준으로 프리랜서를 찾고, 추천 근거를 확인하는 매칭 서비스라는 점을 한 번의 흐름으로 이해하게 한다.

## 5. 디자인 방향

- 배경: 아이보리 또는 아주 연한 회색
- 색상: 검정·회색 중심, 강조색은 한 가지 이하
- 폰트: Pretendard 계열 기본 산세리프
- 분위기: 이력서 첫 페이지와 연결되는 미니멀한 에디토리얼 디자인
- 카드 남용 금지: 여백, 굵기, 구분선으로 정보 분리
- 과한 애니메이션 금지: 등장 효과와 영상 재생 정도만 사용
- 모바일에서도 제목과 핵심 내용이 먼저 보이도록 구성

## 6. 콘텐츠 원칙

- 회사가 모를 프로젝트 용어는 서비스 설명 후 사용한다.
- 기술 이름보다 문제, 판단, 적용, 확인 순서로 설명한다.
- 팀 전체 구현과 개인 구현을 명확히 구분한다.
- 측정하지 않은 성능 개선 수치는 쓰지 않는다.
- 홈에는 결론만, 프로젝트 상세에는 근거를 둔다.
- 한 문단을 3~4줄보다 길게 만들지 않는다.
- 체험은 30~60초 안에 끝나도록 만든다.
- 체험 화면에서 기술 설명을 먼저 보여주지 않는다.

## 7. 제작 순서

1. 홈 구조와 반응형 레이아웃 완성
2. DONDOK 30초 체험 화면 제작
3. DEVNEAR 30초 체험 화면 제작
4. PR 영상·프로필·프로젝트 대표 이미지 교체
5. DONDOK 상세 페이지 제작
6. DEVNEAR 상세 페이지 제작
7. AI 활용 사례는 홈 또는 별도 페이지의 보조 콘텐츠로 배치
8. 이력서·Notion·GitHub 링크 연결
9. 모바일·접근성·오탈자 검수
10. Vercel 배포 및 실제 URL 확인

- 사용할 프로필 사진

- DEVNEAR 대표 화면과 아키텍처 이미지
